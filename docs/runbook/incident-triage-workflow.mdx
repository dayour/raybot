# Incident Triage and Routing

The only multi-branch Coral workflow in this repository assembled one action at
a time, with a screenshot after every command. Seventeen stills, `00` through
`16`, from an empty canvas to a published flow.

Every other workflow record in this repository is either a node-type inventory
(see [Phase 7](./phase-7-reaudit.mdx), which captured thirteen node types in

[Phase 8](./phase-8-showcase-catalog.mdx)). This is the only one that shows a
branch being created, configured, and completed.

## The pattern

```
Start (trigger: text input "incidentText")
  -> Variable  severity = "unclassified"  (String)
  -> Classify  incidentText into { Critical | Standard | Other }
       Critical -> Human review   (Outlook approval: Title / Message / Assigned to)
       Standard -> Agent          (GPT model, free-text triage response)
       Other    -> Note           (sticky: manual-triage fallback, no automated action)
```

Each branch terminates differently on purpose, and the three endings are the
point of the build:

- **Critical** blocks on a person. The workflow stops until someone approves.
- **Standard** delegates to a model. The workflow continues without a human.
- **Other** does nothing automated at all.

The third ending is the unusual one. A Note is a **canvas sticky, not a step** -
it is not wired into the flow and does not execute. Placing one on the Other
branch documents, inside the artefact itself, that the branch is deliberately
unautomated. The alternative - leaving the branch empty - is indistinguishable
from an unfinished workflow.

## The Variable node earns its place

`severity = "unclassified"` is set **before** Classify runs, and Classify never
writes back to it.

That looks redundant, and in this workflow it is: nothing reads `severity`
downstream. It was included to capture the Variable node's configuration surface
- name, Type dropdown, Value field - in a realistic position rather than in
isolation. The generalisable version of the pattern is a pre-seeded default that
downstream branches overwrite, so that a branch which fails to set it still
yields a defined value rather than an empty one.

Branches are completed one at a time - Critical fully configured at `11` before
Standard is started at `12`. That ordering was not aesthetic. Configuring two
branches concurrently means two open config panels competing for the same canvas,
and the designer does not handle that well
([Phase 8](./phase-8-showcase-catalog.mdx#the-agent-config-panel-blocks-the-next-picker)).

## Gotchas confirmed during this build

### Agent Output defaults to Text response, and should stay there

Selecting **Structured output** or **Custom structured output** adds required
property fields, which triggers *"Fix 1 error before publishing"* and reinstates
the **Setup needed** badge on a node that was already clean.

```js
await page.getByRole('option', { name: 'Text response' }).click();
```

Use structured output only when every required property will actually be filled.
This behaviour recurred during the Phase 8 rebuild two days later.

### Escape closes the panel and commits

Pressing Escape while an Output dropdown is open closes the entire node panel
**and commits an unintended value**. Click the desired option explicitly.

### The Note node is a sticky

Test id `action-item-canvasNote`. It is not wired into the flow. Editing it takes
a double-click, which focuses a textarea; set the value, then click empty canvas
to commit. Clicking away without committing discards the text.

### Save and Publish

The Save button carries test id `save-button` and is **disabled when the
workflow is already saved** - a disabled Save is the success state, not a
failure. Publish via:

```js
await page.getByRole('button', { name: 'Publish', exact: true }).click();
```

Publish takes roughly eight seconds. Afterwards the tooltip changes to
*"Republish to re-enable the running flow (no new changes)"* and **Test**
enables.

## What this build does not prove

The workflow published. It was never run.

No incident text was ever submitted to the trigger, so Classify has not been
observed routing anything, the Outlook approval has not been sent, and the Agent
on the Standard branch has not produced a triage response. The three-way branch
is confirmed to be *constructible and publishable*; its routing behaviour is
unverified.
